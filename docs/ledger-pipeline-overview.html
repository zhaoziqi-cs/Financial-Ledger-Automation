Financial Ledger Automation Python · pandas SQLite · ledger.db FastAPI（本地网页） argparse CLI

银行流水进来，一本更新的总台账出去

这是一个“资金台账自动化”项目的全流程解读：银行每个月导出的流水 Excel，怎样被自动清洗、识别出项目、 写进 SQLite（data/ledger.db） 的总台账。代码统一在 src/ledger_etl/，命令行 ledger 一键执行， 本地网页端用 FastAPI（入库为主、下载为辅）。

3张 SQLite 表：暂存 + 主表 + 异常
1张「项目编码 → 名称」映射表
5步完成一次“本期并账”
≈7k行历史明细，仅 init 重建

01 · 主循环

每一期新流水，怎么并入总台账

一次 ledger run 跑两根管道：解析把新流水变成干净的行，并账把本期追加到主表末尾、以上期末余额续算；只有出现更早日期的补录时才会整段重排。绿色框是库表。

02 · 首次建账

开始循环前：先把历史台账灌进主表

主表不是空的开始。用 ledger init 把整理好的历史总日记账（ledger_init.xlsx）一次性灌进 ledger——这是唯一允许全量重建的入口。

03 · 逐步拆解

五个动作，一次“本期并账”

与主循环图一一对应（代码都在 src/ledger_etl/）。暂存为空时并账会直接跳过；同一份流水请勿重复 run（暂未做去重）。

1

解析银行流水 parse_bank_flow.py ledger audit / run

读 bank_flow.xlsx 和 project_map.xlsx：把收款/付款金额、YYYYMMDD 日期标准化；在每条摘要里扫描是否包含某个项目编码，命中就标成对应项目（1220153829#百家坊项目… → 百家坊未来社区），都没命中则记为 “未识别项目”；再按“收到 / 支付 + 流水类型”规整出最终摘要；最后按 日期 + 项目 + 摘要 求和，把同一笔拆成多行、或带重复文本的流水并成一条。

2

写入暂存表 bank_flow

清空后再整批插入，表中只装本期解析结果，与“入账”解耦。注意：它只隔离“解析”与“并账”，本身不防重复——同一流水文件跑两遍会重复入账（见文末取舍）。

3

并账：追加到主表末尾 merge.py

读 bank_flow + ledger。普通情况 = 纯追加：以主表末行余额为锚，按流水顺序逐行 余额 = 上期余额 + 收 − 支，历史行一律不动；暂存为空则跳过。若本期里有早于台账末日的补录，则从补录点起整段重排重算（补录点之后的余额随之更新，属预期）。

4

写回主表 ledger ledger run

新行（含各自的余额）插入主表末尾；补录情况则重排受影响段后写回。最后清空 bank_flow 暂存，回到待机状态，等下期流水。主表即“历史 + 最新一期”的完整台账。

5

交付 ledger.xlsx ledger export-ledger

从 ledger 导出 Excel 给业务，或本地网页 ledger serve 上传后预览 / 下载。“本期并账”完成。

未识别项目怎么办（补映射 → 修正历史）：

ledger audit（干跑）或 ledger run 会把“未识别项目”的原始行写进 unmatched 表待人工核查 → ledger export-audit 导出来核对 → 在 project_map.xlsx 补上编码 → ledger recheck --map 新映射.xlsx：重新匹配，只把主表对应行的项目名改掉，不动金额与余额，并把该异常标为已解决。

04 · 字段对照

中文 Excel 列，怎么落成数据库字段

这是整个映射的关键一张表：银行流水原始 12 列，只取 5 列有用信息，其余（时间、流水号、对方账户…）不进账。金额全程按 2 位小数收敛。

银行流水原始列解析时做什么落库字段说明
交易日期 20260429 int / %Y%m%d → 统一 ISO date TEXT 'YYYY-MM-DD'付款发生日
收款金额 / 付款金额 取数 + round2 income / expense REAL(2位)方向拆成两列，余额就能滚算
摘要 “1220153829#百家坊…” 扫描内置项目编码，去 project_map 里查 project TEXT找不到 → “未识别项目”兜底，不丢行并留痕
流水类型 工程款 有收→“收到+类型”；有支→“支付+类型” summary TEXT直接可读的摘要
—（无） groupby(日期+项目+摘要).sum() 行级聚合一笔拆多行 → 并成一条，账上不重复

历史快照那边同样有张“翻译表”，由 seed.py（ledger init）处理：日记账 sheet（表头第 3 行、列 B:H）里的 日期 → date、项目 → project、摘要 → summary、收 → income、支 → expense、资金净额 → balance，去空行、去序号后整批重建入库。

bank_flow · 暂存表

id INTEGER PK AUTOINCREMENT date TEXT -- 'YYYY-MM-DD' project TEXT summary TEXT income REAL -- 2 位小数 expense REAL -- 2 位小数
  • 生命周期 = 单次运行：装本期 → 被并账读走 → 清空

ledger · 主表（总台账）

id INTEGER PK AUTOINCREMENT date TEXT project TEXT summary TEXT income REAL expense REAL balance REAL -- 滚动余额
  • 普通导入＝追加，历史余额不动
  • 仅 ledger init 整表重建；补录触发局部重算

unmatched · 未识别异常表

id INTEGER PK date TEXT summary_orig TEXT -- 原始银行摘要(含编码) agg_summary TEXT -- 其折叠进的台账摘要 income/expense REAL agg_income/expense REAL status TEXT -- open|resolved|conflict project TEXT
  • run/audit 时给“未识别项目”逐条留痕
  • 补映射后 ledger recheck 匹配并修正主表、标 resolved
  • 导出清单给人工核对（ledger export-audit）

05 · 演进与现状

这个项目是怎么一步步长成今天这样的

三月份从“Excel 手工整理”起步，几经换代到现在这套本地化“脚本 + SQLite + 网页”。按 git 历史还原的路径：

起源 · Excel 手工整理

把几十个项目 sheet 汇总成一册日记账

原始大台账 项目台账0228.xlsx 每个项目占一个 sheet、表头在第 3 行。clean_ledger.py 跳过“融资/上缴/各年累计收款”等汇总 sheet、逐项目读取 → 合并 → 排序 → 重算余额 → 得到一册整理好的总日记账（即后来入库的历史快照 ledger_init.xlsx）。该脚本一次性使用，已删除。

中期 · Flask 网页版（Excel 进 / Excel 出）

浏览器上传 → 下载更新后的 ledger.xlsx（无数据库）

调 parse_bank_flow → update_ledger 直接在内存合成并返回文件。app.py / templates / static / render.yaml 都是这一版。README 曾描述的就是这套；现已随重构删除。

之后 · MySQL 入库版

加了一层 MySQL：暂存表 + 主表

bank_flow/ledger 两张表 + pymysql，把解析结果写暂存、并入主表。依赖本机 MySQL 服务、密码明文写死在代码里——这也是本次想改掉的地方。

本次重构 · 本地化（当前，改动未提交）

src 统一代码 + SQLite + FastAPI 本地端 + 异常修正流程

代码收进 src/ledger_etl/（路径与 cwd 无关）；存储换成 SQLite（data/ledger.db）并加第三张 unmatched 异常表；并账改成纯追加（普通导入不再整表重写历史，只有补录才局部重算）；网页端换成 FastAPI 本地 serve，删去 Flask / render.yaml / gunicorn；补了 audit / recheck / export 等命令和 pytest（30 项）。fund_etl 里那套“分公司分组行 + 表头错行”的清洗被收编为 cleaner.py（未接入管道）。

现在怎么跑（本地单机）：

pip install -e ".[dev]"
ledger init # 建库：从 data/raw/ledger_init.xlsx 灌历史
ledger run data/raw/bank_flow.xlsx # 本期并账（入库为主）
ledger audit data/raw/bank_flow.xlsx # （可选）干跑看未识别
ledger recheck --map <新映射.xlsx> # 补映射后修正历史项目
ledger export-ledger --out ledger.xlsx # 交付下载
ledger serve # http://127.0.0.1:8000

改动均未提交；data/ledger.db 在你第一次 ledger init 时才生成（gitignore）。已知取舍：同一份流水别重复 run（暂未做去重）。
